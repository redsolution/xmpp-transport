# TLS для соединения XMPP-компонента

## Цель и границы

Шифровать соединение `xmpp-transport` с Xabber Server целиком, включая авторизацию компонента, сообщения и roster IQ. Использовать прямой TLS: сервер начинает TLS сразу после TCP-подключения, до открытия XML-потока. STARTTLS для текущего XEP-0114 listener недоступен.

Допустимые изменения сейчас: `xmpp-transport` и `module-transport`; в `xabber-server-panel` — правки, связанные с настройкой `tls: true` для компонентов. Загрузку сертификата через UI пользователь выделил как будущую задачу. Код `xabber-xmpp-server` и материалы `xabber-knowledge` не менять.

Пункты ниже выполняются по указанию пользователя. После реализации и проверки выбранного пункта дописывать «— выполнено» рядом с его заголовком. До этого оставлять пункт без отметки.

## Как должно работать

1. Транспорт открывает TCP-соединение по `server_ip:server_port`.
2. Сервер с `tls: true` и транспорт выполняют TLS handshake. Транспорт проверяет цепочку сертификата и его DNS-имя.
3. Только после успешного TLS транспорт открывает XEP-0114 поток и проходит авторизацию по `component_password`.
4. Сообщения и IQ используют тот же защищённый поток. При любой ошибке TLS нет перехода на открытый текст.

Имена имеют разные роли: `server_ip` — адрес TCP-подключения; `component_tls_server_name` — DNS-имя, которое должен подтверждать сертификат сервера; `component_jid` — JID транспортного компонента; `server_domain` — адресат серверных roster IQ. При подключении к `127.0.0.1` проверять сертификат по DNS-имени, указанному отдельно, а не по `127.0.0.1`, если сертификат не содержит IP SAN.

## Пошаговая работа

Отложенная задача для панели: добавить в UI компонента загрузку серверного TLS-сертификата с закрытым ключом и формирование `certfile` для TLS listener. Сейчас путь к сертификату для локальной проверки добавляется вручную; эту задачу не считать частью уже выполненного пункта 4.

### 1. Зафиксировать версию и способ настройки slixmpp — выполнено

- В установленном slixmpp 1.10.0 `ComponentXMPP` по умолчанию допускает открытое соединение. Его `connect()` не принимает `use_ssl`.
- Для этой версии перед `connect()` задать `tls_services` непустым значением, `enable_direct_tls = True`, `enable_plaintext = False`, `enable_starttls = False` и `default_domain = component_tls_server_name`. При явно заданном `server_ip:server_port` slixmpp использует их как TCP-адрес, а `default_domain` — как `server_hostname` TLS. Это проверено по локальному коду библиотеки и изолированной проверкой выбора способа подключения, но не на живом сервере.
- Ранее `pyproject.toml` разрешал версии slixmpp от 1.8 до 1.10 с разным API подключения. Файл удалён как устаревший; поддерживаемая версия закреплена как 1.10.0 в `requirements.txt`. Одно только `enable_starttls = True` не защищает соединение.

### 2. Добавить настройки транспорта — выполнено

- Добавить в `ComponentSettings` режим прямого TLS, имя сервера для проверки сертификата и необязательный путь к файлу доверенного CA. Валидировать сочетания: при включённом TLS имя обязательно, пустой/несуществующий CA-файл — ошибка конфигурации.
- Передавать эти значения из `runtime/composition.py` через параметры backend INI, например `component_tls = true`, `component_tls_server_name = xmpp.example.com`, `component_tls_ca_file = /path/to/ca.pem`.
- Обновить генератор конфигурации, примеры MAX/Telegram и README. Отдельно пояснить, что `server_ip` остаётся адресом подключения и может быть IP-адресом.
- Не выводить компонентный пароль или содержимое сертификатов в логи.

### 3. Изменить подключение компонента — выполнено

- В `adapters/xmpp/component.py` настроить выбранный TLS API slixmpp до вызова `connect()`.
- Использовать проверку сертификата (`CERT_REQUIRED`) и имени сервера (`check_hostname=True`); системные CA по умолчанию, указанный CA-файл — при необходимости для частного центра сертификации.
- Не разрешать `session_start`, отправку сообщений и `request()` до успешного TLS. Исключить попытку подключения по открытому тексту после ошибки TLS или сертификата.
- Сохранить нынешнее переподключение и завершение фоновой задачи; сообщения об ошибках в журнале должны содержать только безопасные метаданные.

### 4. Добавить единственный необходимый флаг в панели — выполнено

- В UI компонентов `xabber-server-panel` добавить переключатель `tls` и сохранить его в модели компонента.
- Шаблон генерации listener `ejabberd_service` должен выводить `tls: true` только для включённого флага. Нужную миграцию поля панели выполнить в рамках этого изменения.
- Убедиться, что сервер предъявляет сертификат с DNS-именем `component_tls_server_name`; если используется частный CA, предоставить транспорту его сертификат. Код сервера не менять.

### 5. Проверить поведение до включения на рабочих компонентах — выполнено

- Локальные автоматические проверки добавлены в `tests/test_xmpp_component_tls_integration.py`: TLS и roster IQ, отказы при неверном имени и недоверенном CA, обычный listener и повторное TLS-подключение. Все пять тестов пройдены на `127.0.0.1` с тестовым XEP-0114 listener. Проверка на настоящем ejabberd listener остаётся отдельным действием.
- Для локальной проверки созданы `local-tls/server.pem` (сертификат и закрытый ключ для DNS-имени `localhost`) и `local-tls/ca.pem`; `max.config.ini` настроен на TLS с этим CA. Файлы сертификата ещё нужно разместить в каталоге, из которого ejabberd загружает `certfiles`, и включить `tls` у соответствующего компонента через панель.
- На локальном ejabberd 2026-10-23 одних `tls: true` и глобального `certfiles` оказалось недостаточно: listener сбрасывал TLS с ошибкой `no_certfile`. После ручного добавления `certfile` в listener MAX OpenSSL подтвердил TLS 1.3, сертификат `localhost` и `Verification: OK`; журнал ejabberd подтвердил принятую XEP-0114 авторизацию `max.example.com` по TLS. Пользователь подтвердил, что авторизация работает и контакты сохраняются через запущенный MAX транспорт. Сервер предупреждает, что его собственный список CA не доверяет локальному CA; проверка сертификата транспортом через `component_tls_ca_file` проходит.
- Автоматически проверить выбор **только** TLS-подключения в поддерживаемой версии slixmpp и отсутствие plaintext fallback.
- Проверить успешное соединение и roster IQ с тестовым TLS listener; отдельно отказ при неверном имени, недоверенном сертификате и обычном plaintext listener. При отказе не должно уходить XML, авторизация компонента или IQ.
- Проверить, что после разрыва повторное соединение снова требует TLS и проверку сертификата.
- На целевом listener проверить сертификат, например: `openssl s_client -connect 127.0.0.1:5237 -servername xmpp.example.com -verify_hostname xmpp.example.com -verify_return_error` (для частного CA добавить `-CAfile /path/to/ca.pem`).
- На живой проверке подтвердить, что TCP-соединение начинается с TLS handshake, а XEP-0114 handshake и IQ появляются только после него. Не включать подробные логи XML или содержимого сообщений.

### 6. Включить согласованно для каждого backend

1. Подготовить сертификат сервера и доверенный CA, если нужен; настроить и проверить DNS-имя сертификата.
2. Подготовить и проверить конфигурацию транспорта с `component_tls = true`, правильными `server_ip`, `server_port` и `component_tls_server_name`.
3. Остановить конкретный backend, включить `tls` для его компонента в панели и применить конфигурацию сервера.
4. Запустить backend, подтвердить TLS, XEP-0114 авторизацию, отправку/ответ roster IQ и доставку сообщения.
5. Повторить отдельно для второго backend. Между переключением listener и транспорта возможен короткий перерыв соединения; открытый fallback не допускать.

## Основание в текущем коде

- `xmpp_transport/adapters/xmpp/component.py`: сейчас вызывает `ComponentXMPP.connect()` без TLS-настройки.
- `xmpp_transport/runtime/composition.py`: формирует `ComponentSettings` из `server_ip`, `server_port` и `component_password`.
- `xabber-xmpp-server/src/ejabberd_service.erl`: поддерживает опцию listener `tls`.
- `xabber-xmpp-server/src/xmpp_stream_in.erl`: при `tls: true` устанавливает TLS до XML-потока.
- `xabber-server-panel/xabber_server_panel/templates/config/components_config.yml`: сейчас не выводит `tls` для компонентов.
